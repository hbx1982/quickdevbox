Network Latency & BDP: Speed of Light in Fiber, RTT & Bufferbloat Math

Network latency measures the Round-Trip Time (RTT) of data packets traversing physical transmission channels. The theoretical minimum latency is bounded by the speed of light in vacuum (c) and single-mode optical fiber (~200,000 km/s).

Speed in Glass Fiber ~200 km per millisecond (~200,000 km/s / refractive index ~1.468)
Bandwidth-Delay Product (BDP) BDP = Bandwidth (bits/sec) * RTT (seconds)
TCP Flow Control TCP Receive Window (RWIN) scaling (RFC 7323)
Latency Components Propagation delay + Transmission delay + Queuing delay + Processing delay

Implementation & Code Examples

Python BDP Calculator

def calculate_bdp(bandwidth_mbps, rtt_ms):
    # Convert Mbps to bits per second and ms to seconds
    bandwidth_bps = bandwidth_mbps * 1_000_000
    rtt_sec = rtt_ms / 1000
    bdp_bits = bandwidth_bps * rtt_sec
    bdp_bytes = bdp_bits / 8
    return {"bdp_bytes": int(bdp_bytes), "bdp_kb": round(bdp_bytes / 1024, 2)}

Frequently Asked Questions & Troubleshooting

Why can network latency between New York and London never be lower than ~35ms?

The great circle distance is ~5,570 km. In optical fiber glass (light speed ~200 km/ms), one-way propagation takes 27.8ms, yielding an absolute theoretical round-trip physical limit of ~55ms over real terrestrial routing cables.

What is Bufferbloat and how does it inflate network ping times?

When routers have oversized unmanaged packet queues, bulk downloads fill the queue, forcing latency-sensitive packets (like DNS lookups or VoIP) to wait hundreds of milliseconds. Modern AQM algorithms (like CoDel or FQ-CoDel) solve this.
