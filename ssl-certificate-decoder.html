X.509 Certificate Decoding: ASN.1 DER Structures, SAN & PKI Validation

SSL/TLS certificates use the ITU-T X.509 standard to bind cryptographic public keys to domain identities. Parsing certificate PEM blocks decodes ASN.1 DER data structures, checking validity timestamps, Subject Alternative Names (SAN), and issuer chains.

PKI Standard IETF RFC 5280: Internet X.509 Public Key Infrastructure Certificate
Encoding Formats Base64 PEM (ASCII Armor) and Binary DER (Distinguished Encoding Rules)
Identity Extension Subject Alternative Name (SAN, id-ce-subjectAltName)
Signature Cryptosuites ECDSA with SHA-256 (P-256) | RSA 2048/4096 with SHA-256

Implementation & Code Examples

OpenSSL CLI Certificate Inspection

# View human-readable certificate details
openssl x509 -in cert.pem -noout -text

# Check expiration date and Subject Alternative Names
openssl x509 -in cert.pem -noout -dates -ext subjectAltName

Node.js (tls module certificate inspection)

import tls from 'tls';

const socket = tls.connect(443, 'quickdevbox.com', { servername: 'quickdevbox.com' }, () => {
  const cert = socket.getPeerCertificate();
  console.log("Issuer:", cert.issuer.O);
  console.log("Valid To:", cert.valid_to);
  console.log("SANs:", cert.subjectaltname);
  socket.destroy();
});

Frequently Asked Questions & Troubleshooting

Why are Common Name (CN) attributes deprecated in favor of Subject Alternative Names (SAN)?

RFC 6125 and the CA/Browser Forum formally deprecated Common Name matching because CN only accommodates single hostnames and lacks strict type parsing. Modern browsers require domain identities in the SAN extension.

What causes 'SSL Certificate Problem: unable to get local issuer certificate'?

The server failed to provide the intermediate CA certificate in its TLS handshake bundle (incomplete certificate chain). Web servers must serve the full certificate chain (fullchain.pem), not just the leaf certificate.
