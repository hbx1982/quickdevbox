Comprehensive Guide to HTTP Response Status Codes

HTTP status codes are three-digit numeric responses generated by origin servers or intermediate proxies to communicate the result of processing an incoming HTTP request. Standardized by RFC 9110, status codes govern RESTful API semantics, browser caching behaviors, and proxy failure handling.

1. Classification of HTTP Status Classes

  • 1xx (Informational): Request received, continuing process (e.g. 101 Switching Protocols).
  • 2xx (Successful): Action requested was successfully received, understood, and accepted (e.g. 200 OK, 201 Created).
  • 3xx (Redirection): Further action must be taken to complete request (e.g. 301 Moved Permanently, 304 Not Modified).
  • 4xx (Client Error): Request contains bad syntax or cannot be fulfilled (e.g. 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found).
  • 5xx (Server Error): Server failed to fulfill an apparently valid request (e.g. 500 Internal Server Error, 502 Bad Gateway, 503 Service Unavailable).

2. Diagnosing 502 Bad Gateway & 504 Gateway Timeout Errors

A 502 Bad Gateway indicates that Nginx, HAProxy, or Cloudflare received an invalid response from an upstream application server (like Node.js, Gunicorn, or PHP-FPM). In contrast, 504 Gateway Timeout indicates that the upstream server failed to respond within the configured proxy read timeout window.
