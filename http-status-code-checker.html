HTTP Status Codes: RFC 9110 Semantics, Redirection Classes & Server Diagnostics

HTTP status codes indicate the result of a client request using 3-digit integers categorized into five distinct classes (1xx Informational, 2xx Success, 3xx Redirection, 4xx Client Error, and 5xx Server Error) governed by RFC 9110.

HTTP Specification IETF RFC 9110: HTTP Semantics (Replaces RFC 7231 / RFC 2616)
Class Hierarchy 1xx (Info), 2xx (Success), 3xx (Redirect), 4xx (Client), 5xx (Server)
Redirect Semantics 301/302 (May change POST to GET) vs 307/308 (Method Preserving)
Caching Behavior Heuristically cacheable codes (200, 204, 301, 404, 410, 501)

Implementation & Code Examples

Node.js (HTTP Response Handler)

import http from 'http';

const server = http.createServer((req, res) => {
  if (req.url === '/api/data') {
    res.writeHead(200, { 'Content-Type': 'application/json' });
    res.end(JSON.stringify({ status: 'ok' }));
  } else {
    res.writeHead(404, { 'Content-Type': 'text/plain' });
    res.end('Resource Not Found');
  }
});

Frequently Asked Questions & Troubleshooting

What is the difference between a 301 Moved Permanently and a 308 Permanent Redirect?

Historically, browsers rewritten POST requests to GET upon receiving 301 redirects. RFC 7538 introduced HTTP 308 to guarantee that the HTTP request method and body (POST/PUT/DELETE) are preserved verbatim.

What is the difference between 401 Unauthorized and 403 Forbidden?

HTTP 401 means authentication is required and missing or invalid (response MUST include WWW-Authenticate). HTTP 403 means the server understands the user's authenticated identity but refuses to authorize access.
